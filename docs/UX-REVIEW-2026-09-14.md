# PDF.MV UX review — 14 September 2026

**Verdict: Approve with changes.** Keep the green identity, neutral surfaces, document tabs and local-file model. Prioritize a consistent editing workflow before another visual redesign.

This is a heuristic review of the current production interface and its implementation, informed by Mobbin screens/flows and Built for Mars MCP research. It is not a usability study or a claim that every PDF engine has passed functional testing.

## Scope and evidence

- Inspected production Home, Convert and Combine entry flows, desktop screenshots/accessibility trees, and a 390px responsive check. Used source review for watermark preview/apply, session state, native signature controls and responsive behavior.
- Existing validation previously demonstrated opening a synthetic PDF, downloading it, and a successful watermark preview. The earlier raw import error is evidence of poor error presentation, not proof that production watermark preview remains broken.
- Mobbin: visually examined PandaDoc importing/editing, Craft export/settings and document information, and Fibery selection controls.
- Built for Mars: used `bfm_analyze_lessons`. Exact-content searches returned tool errors; a web fallback exposed only the site shell. BFM recommendations below rely on the MCP-returned excerpts and source summaries, not a claimed full-article review.
- No private user documents were sent to research services. No app code, production settings or deployment changed for this review.

## What to retain

- Home plus internal task/document tabs; tested Convert and Combine both opened internal tabs.
- Six popular groups on Home, with a larger library available. The problem is not 23 cards appearing at once.
- Left page navigation, central document, right contextual controls.
- Deep green primary actions, neutral dark surfaces, light/dark/auto modes.
- Native signature Draw/Type/Upload, color selection and adjustable smoothing.
- Local processing, no account gate, direct download, original-file protection.
- The requested 32px outlined Upload button on desktop. Increase its touch hit area on coarse-pointer devices without forcing a larger desktop design.

## Target flows

### Open a PDF and edit

Open PDF → document tab → select a right-panel tool → adjust settings while viewing the document → preview in place → apply → download.

The active document is the default source. Do not ask users to upload it again. Tool changes keep page, zoom, selection and file context. A preview is visibly temporary; cancel restores the committed document. Applying creates an undoable revision only after the shared history mechanism is reliable. Until then, explicitly label “Create edited copy.”

### Start from a Home tool

Choose tool → internal task tab → compact source picker → loaded document in the same tab → same contextual controls as the file-first flow.

The initial empty canvas may offer a direct Choose files action that invokes the same picker as the sidebar. It should not merely point users to a distant control. Changing tools must not silently discard selected inputs.

### Convert

Choose files → detected input summary → output format → optional settings → convert → inspect output / download.

- Show only formats supported for the selected input. Support mixed images as one understandable input type.
- For non-previewable source formats, show filename, type, size and conversion state; display the PDF once created.
- Explain likely formatting limitations where relevant. Avoid promising exact Word/PDF round trips.
- Show first-use engine loading separately from conversion. Use measured progress when available; otherwise honest phase labels and cancellation where technically supported.
- For multiple outputs, offer the appropriate files or ZIP. Do not leave the header saying “Download PDF” when the output is another format.

### Combine and organize

Add files → page grid grouped by source → reorder/select → merge → resulting PDF in the workspace.

- Default to pages with uniform thumbnail sizes and clear source labels; offer Files view for large jobs.
- Replace the large loaded-state upload box with Add files and a compact source list.
- Offer Move earlier/later and keyboard selection alongside drag-and-drop.
- Put output filename, page count and Merge action in a sticky footer. Advanced options remain available in a disclosure.
- Lazy-render thumbnails for large inputs; do not render hundreds of full-resolution pages immediately.

### Sign

Open document → Sign → Draw / Type / Upload → place → move or resize → download.

Retain the native controls already built. Put certificate signing and signature validation under a clearly named advanced section so they are not confused with adding a visible signature. Keep the existing explanatory distinction. Show placement mode clearly and let Escape cancel placement.

## Shared component contract

| Component     | Required behavior                                                                                                                               |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Tab           | Distinguishes empty task, loading document, loaded document and edited document; accessible close control; stable identity during tool changes. |
| Source picker | Choose files, use an open document, file summary, replace/add actions; same behavior across native and migrated tools.                          |
| Tool panel    | Title and Back to tools, short purpose, essential fields, advanced disclosure, sticky primary action.                                           |
| Page scope    | All pages by default; selected pages or explicit range when needed; validation next to the field.                                               |
| Preview       | Main canvas, clearly marked temporary state, compare/cancel; stale previews invalidated after settings change.                                  |
| Progress      | Phase and actual progress where available; prevent duplicate submission; retain settings.                                                       |
| Error         | What failed, whether the document is safe, a relevant recovery action, optional technical details.                                              |
| Result        | Correct filename/type; obvious download; continue editing where supported; no compulsory extra success dialog.                                  |
| Mobile tools  | One focused surface at a time, accessible icon buttons, reachable sticky action, no nested long-page scrolling.                                 |

## Research references and application

1. [PandaDoc editor — Mobbin](https://mobbin.com/screens/230401d4-b673-43f5-a6e6-c49f5085cade): left page thumbnails, central canvas, grouped right tools and page-local menu. Strongest structural reference for PDF.MV. Borrow grouping and context, not account/collaboration features.
2. [Craft PDF export flow — Mobbin](https://mobbin.com/flows/951d22bd-d57f-4619-bcfa-f864291350a4): settings next to a substantial output preview. Apply this to watermark, headers/footers and export. PDF.MV can download directly without copying its additional success modal.
3. [PandaDoc import flow — Mobbin](https://mobbin.com/flows/af5dcf74-97b3-4cc4-ae22-15c7378e0a55): filename and cancellable progress preserve context during import, followed by the editing surface. Do not adopt recipients, trials or cloud onboarding.
4. [Craft document information — Mobbin](https://mobbin.com/screens/8bc2c4e6-34cd-4478-900c-b0c0c8f8da3f): grouped contextual information and lightweight completion feedback.
5. [Fibery inline editing — Mobbin](https://mobbin.com/screens/40ad6297-5ada-4003-b980-5aa0063dd328): selection-local text controls. Useful for annotation actions, not a model for the entire PDF shell.
6. [Monzo vs Starling: Overdrafts — Built for Mars](https://builtformars.com/case-studies/applying-for-an-overdraft): the MCP excerpt describes selectively revealing information behind relevant actions. Our inference: keep advanced PDF settings available without presenting them all initially.
7. [How to Stop People from Skipping Your Onboarding — Built for Mars](https://builtformars.com/case-studies/ynab): the MCP excerpt describes users preferring forward-moving actions to upfront instruction. Our inference: begin conversion with file selection, then ask relevant questions.

These are transferable patterns, not evidence that copying them will improve PDF.MV by a particular percentage. No account, upsell, forced tour or paid workflow is needed.

## Implementation sequence and acceptance criteria

1. **Shared state and accessibility:** correct empty-task labels/counts, name the mobile tools button, standardize errors and action states. Verify Home/task/document transitions with keyboard and screen reader.
2. **Unify one complete flow:** migrate Merge to native source/options controls and central page preview. Confirm file-first and tool-first produce the same behavior, including adding files, ordering, cancel and download.
3. **Preview and revision model:** central watermark/header-footer previews, sticky actions, safe cancellation. Add reliable undo before changing copy-based apply semantics. Switching tools must retain edits.
4. **Conversion and library simplification:** detected inputs, compatible outputs, shorter Home, one category navigation per viewport.
5. **Responsive and polish pass:** test 390, 768 and 1280px, both themes, long filenames, keyboard-only operation, touch reordering, 1/50/500-page documents and engine-load failure. Respect reduced motion and avoid layout jumps.

Before broad rollout, run a small moderated test with five people: open/sign/download; combine two PDFs; convert Word to PDF; watermark selected pages; recover from an invalid file. Record completion, wrong turns, re-uploads and uncertainty about which file will download. Use a baseline before setting improvement targets; do not collect document contents.

**Recommended next implementation:** shared state fixes plus the native Merge flow. This establishes reusable components for the remaining tools and addresses a directly observed inconsistency.
