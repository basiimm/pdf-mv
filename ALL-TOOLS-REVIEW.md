# Complete tool and flow review

Reviewed 14 September 2026. The catalog contains 118 engines, consolidated into 23 task groups. Every source route, declared purpose, file controls and initialization pattern was inspected. Runtime coverage is recorded separately; source review does not certify every conversion or export.

## Decisions

- Home opens a new application task tab. A tool selected inside a PDF acts on that document. Switching an action or output format stays in the same task.
- Convert is one entry: Create a PDF → source format, or Export a PDF → output format. PDF/A belongs here; grayscale and OCR do not change file format and live under Appearance / Recognize text.
- Page manipulation and simple marks belong beside the PDF. Large interactive editors, comparison, and workflows use the task canvas.
- Numbering groups headers, footers, page labels and Bates numbering without pretending these are identical. Signatures keeps drawn marks separate from certificate signing and validation.
- Search includes all original tool names. No capability disappears when its Home card is consolidated.
- Native panels return an edited copy; originals remain available. More options opens the original engine for advanced settings, preserving the open PDF (or selected images) in the same task. Existing processing engines remain embedded where a dedicated native adapter has not been implemented.

## Interaction issues found

- Page-load readiness was used as file-input readiness. OCR initializes its input after awaiting translations; JSON import also initializes asynchronously. They now send an explicit input-ready signal.
- There was no input acknowledgement or visible retry state. Embedded tools now report transport status and offer Use current PDF to start again with the latest document. A transport acknowledgement is not a processing-success claim.
- Form filling and PDF comparison were put in a narrow sidebar despite containing their own document canvases. They now use the large application canvas.
- Tool names were scattered across dozens of conversion cards. A single shared registry now drives both Home and the document sidebar.

## Validation

- Catalog tests require all 118 engines to appear in exactly one group and resolve to a source page. Search tests cover every original tool name.
- Document-operation tests check selected-page rotation, extraction order, deletion guardrails, reverse order, insertion position, metadata removal and form-widget preservation.
- All 23 Home groups were clicked in the live browser; each created and selected an application tab. A first bulk run timed out near the end, then the full check passed in smaller batches.
- Live document test: extract pages 2 and 4 from a 60-page fixture, then reuse the result for text and PNG export. Downloaded text contained exactly the two selected page labels; PNG was a valid 892 × 1262 image.
- Live retained-engine test: Page Numbers received the two-page PDF without another upload, applied numbering and returned a new PDF tab.
- Live multi-image test: choose two PNGs, reorder them with the accessible move controls, then create a two-page PDF.
- Live advanced-options test: switching a selected PNG from native controls to the original converter retained the image and exposed its quality settings without another upload.
- Live Office test: DOCX → PDF → text. The downloaded text matched the fixture content, “BentoPDF conversion test”.
- TypeScript passed. All 941 tests across 53 test files passed. The full suite caught and helped fix the native preview/export worker configuration.

## Remaining limits

- 18 original capabilities currently route to native viewer controls; 90 use embedded settings beside the PDF; 10 use a large canvas within an app tab. This review does not claim that all 118 exports were exercised end to end.
- Native watermark and header/footer text currently use a Latin font. Image watermarks and more advanced options remain accessible through the Watermark type selector.
- Office and some advanced conversions load large browser engines on demand. Output quality still depends on the source format and content; format availability is not a fidelity guarantee.
- PDF processing returns a copy. It does not add a cross-engine undo history to the original document.
- Older browser instances keep their previously loaded workspace code. A fresh grouped-workspace preview was opened separately to preserve existing document sessions.

## Signature workspace integration

Handwritten signing now uses the default viewer with Draw, Type and Upload controls in the right panel. Page placement uses the existing image annotation tool; PDF upload stays in the panel. Certificate signing, validation and timestamp settings remain embedded beside the same PDF, with compact file and certificate controls. Unedited PDFs retain original bytes when passed to these certificate tools.

Validation: all 944 tests passed. Browser checks covered signature-first PDF upload, typed/drawn/image placement, native viewer continuity, and the certificate action layouts. An exported test PDF was independently checked for a stamp annotation. Corrected image sizing was visually checked after detecting an initial appearance clipping issue. No real certificate or external timestamp service was exercised during this UI integration.
